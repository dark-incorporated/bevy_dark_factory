## An optimisation that measured true and helped nothing

`every_selected_row_reads_at_aa_contrast_in_every_skin` built 27 editors inside one test. Split into one per skin:

| | test time | gate |
|---|---|---|
| before | **48.304 s** (1 test) | 767 s |
| after | **16.555 s** (3 tests) | **773 s** |

**The test got 2.9× faster and the gate did not move.** The gate sets `NEXTEST_TEST_THREADS=4`, so three 16.5 s tests
compete for four slots where one held a slot for 48.3 s: 49.5 slot-seconds instead of 48.3. My first report said
"341 s → 107 s", which was the wall of a *one-test run* where the compile dominated — a true measurement and a
misleading one. The branch (`fix/672-split-tests`) is gated at 5,221/5,222 and left unmerged.

**The rule this earns:** splitting a serial test shortens a gate only when the suite is slot-bound. This one has
2,838 tests across four slots, so the fix that would shorten `gate.log` is to **reduce the work**, not to spread it.
