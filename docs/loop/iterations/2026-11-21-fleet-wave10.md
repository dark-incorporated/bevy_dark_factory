**Date:** 2026-11-21
**Outcome:** five releases, **0.7.4** (the name, the icon, the folders), **0.7.5** (the in-app links), **0.7.6** (long names wrap in their panels, the terminal at very large text), **0.7.7** (the Markdown editor wraps and draws in colour, and nineteen of the twenty-two poll timers are replaced by one watcher) and **0.7.8** (long names wrap in INSPECTOR, COMPOSE and ANIMATION, and the Audit row and the agent guide follow their files), each gated (0.7.4 and 0.7.5 at **5,048 / 5,048**, `main` `21fc2e35`, 842 s; 0.7.6 at **5,061 / 5,061**, `main` `902f4518`, 801 s; 0.7.7 at **5,120 / 5,120**, `main` `65bdea82`, 1,059 s; 0.7.8 at **5,122 / 5,122**, `main` `283a23ba`, 899 s, on its second attempt) and verified from the published page; seven issues closed (#518, #534, #497, #494, #533, #535, #501); gooey's loop, dead for 14 days, running again and having delivered everything this editor asked of it. **Two claims in this report's own history were wrong and are corrected below** (a half-size window in the census behind #494 and #535). ## What changed

- **The name.** "Dark Factory", two words, in prose, UI, banner and docs (81 files, six commits). The plist, `build_app.sh`, the release workflow and the asset names follow: `Dark Factory.app`, `Dark-Factory-<V>-macos-arm64.{dmg,zip}`, volume "Dark Factory", release title "Dark Factory <V>". Kept one word on purpose, because they are identifiers and not prose: the User-Agent `DarkFactory/<v>`, `TERM_PROGRAM`, `~/Library/Caches/DarkFactory` and `Application Support/DarkFactory/feedback`.
- **The consequence.** `update.rs` looks for `Dark-Factory-<v>-macos-arm64.zip` with no fallback, so 0.7.1 to 0.7.3 cannot update themselves and must be reinstalled once from the DMG. A fallback to the old asset name would be a second path that installs a differently named bundle over the old one. About one install exists (each zip had been downloaded once).
- **The bundle identifier** is now `io.github.dark-incorporated.dark-factory`, folded into the same one-time reinstall.
- **Folders.** The folders the app makes in Documents are `Dark Factory Projects` and `Dark Factory Example`. Nothing is migrated: the owner's Documents only held `Cauldron Projects`.
- **#518.** `HEADING` is 11 px, so a heading outranks the 10 px label it heads (owner decision).

## Decisions

- **Icon A**, and the model switch (every worker, reviewer and loop agent on `anthropic/claude-sonnet-5-5`; the two `therapist` agents stay on Opus 5.5), both saved permanently.
- **Reinstall once, no updater fallback, and a new bundle identifier.** One install exists; a shim would be a second path.
- **No migration of the folder names**, because nothing exists on the owner's disk to orphan.
- **0.7.4 before the link fix**, so the name and the icon were in the owner's hands first; 0.7.5 then doubles as the test that the renamed in-app updater works end to end.
- **#497: the window wins.** The terminal bar clips instead of pushing the pane past the window, so at text scale 3.0 the Invoke button is clickable; the maximised terminal's restored column count is 8 → 9, re-pinned with the owner's reason.
- **#525: soft wrap and syntax highlighting**, requested of gooey as bevy_gooey#114. **#501: approved and staged**, stage 1 first. **#494 stays open**: both local projects are empty.
- **#525: wrap and ink by file extension, no setting** (assumed while the owner is away): Markdown and plain-text pages wrap and are inked, YAML, RON and Rhai stay as they are. A persisted Files setting through the existing settings layer, using gooey's own type, is cheap to add if wanted; the worker records the decision and that alternative on the issue.
- **A protected test deleted with its subject** (wave 11, `anim_watch`): `a_file_still_being_written_never_promotes` went with `promote()`, the poll's mechanism, and an end-to-end test states the property. Accepted on the owner's behalf as an `Owner exception`; for the owner to confirm or refuse.
- **Review overlaps the queue.** The cargo slot, not review, is the bottleneck, so each worker's branch is read by an independent reviewer from the worker's own worktree (read-only `ssh`, `git diff`, no cargo) while the worker waits, and the findings reach the worker before its final report.
- **Split the gate so what is ready ships.** Wave 11's six branches were all waiting in the cargo queue behind each other, and #494 (reviewed twice) did not depend on any of them. Gating it alone made the queue wait about 15 minutes (the gate holds the exclusive lock), shipped #494 and #497 before wave 11, and leaves wave 11's gate with fewer changes to bisect if it fails. Wave 11 becomes gate #7 and 0.7.7.
- **Fewer agents, more of the work done directly.** The owner asked (2026-11-22) for at most two subagents at once until end of day. The six already running finished; after that, reviews of small diffs, the diagnosis of the one failing settings test (four probe runs in a scratch worktree, then one fix) and the integration of seven branches were done in the manager session rather than by more agents, and one reviewer at a time was kept for the large diffs.
- **The #525 default stands, and the issue stays open.** Wrap and Markdown ink by file extension shipped; the owner's note also asked for a setting to pick a syntax-highlighting theme and polish like VSCode, PyCharm and Obsidian, which are not done and are listed on the issue rather than counted as done.
- **A racy test is fixed by stating the property, not by rerunning the gate.** Gate #8's one failure cost 16 minutes, and a rerun would probably have passed and left a test that fails one gate in several. The cause was in the index's own code (two batches for one change), found by reading `project_index.rs`, and the fix was verified on its own (15 of 15 stress iterations) before the second gate was spent.
- **#501 closes on an assumed decision.** Its four acceptance boxes are met and twenty of its twenty-two constants are retired; the two that stay (`STATE_POLL_S`, `LOG_POLL_S`) are exceptions I recorded and labelled `assumed-decision`, which the owner reverses by reopening the issue. What the issue's own count missed became #538, and the ratchet written for it was found to match names, not behaviour.
- **Findings go to the tracker with their evidence level.** #537 (panel bodies have no room at the top of the interface-size range in a small window: measured by the corrected census, not seen on a screen), #538 (six UI-thread clocks found by a regex scan of every crate and then read by hand: costs not measured) and `bevy_gooey#116` (a `SyntaxTheme` for #525's theme setting) were filed with what is established and what is not.

## Wave 11: the reviews that ran while the cargo queue drained

Six workers (five on #501, one on #525) shared one cargo slot. A run took 5 to 8 minutes and the queue held up to eight, so a worker spent most of its time waiting. A reviewer does not need the slot, so each branch was read before its worker reported. No reviewer ran anything: every "would fail" below is a reading of the code, not a result, and none of the fixes is verified yet.

|Branch|What the review found|
|---|---|

|data, notes, oplog and checks views|**blocker:** a temporary `W501B_MUT` environment-variable hook for mutation runs, called from production code in all four views; guide text still describing the retired behaviour; an assertion that cannot fail|
|problems, world lists, reference view, night shift|a `.gitignore` re-read on every index generation for every project that lacks the module's file, so an unrelated change made about five lists read from disk (its own counter test could not see it)|
