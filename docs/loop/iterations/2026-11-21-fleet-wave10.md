# Fleet wave 10 — the release that shipped without a name or an icon

**Date:** 2026-11-21
**Outcome:** two releases, **0.7.4** (the name, the icon, the folders) and **0.7.5** (the in-app links), each gated at **5,048 / 5,048** (`main` `21fc2e35`, 842 s) and verified from the published page; #518 closed; gooey's loop, dead for 14 days, running again. The wave is still open: 7 issues remain and this report is updated as each lands (see "What remains").

## "Has a new release been put out?"

The owner asked, and added that the organization and repository structure had changed. Measured, not remembered:

- The latest release was **0.7.3** (tag `bevy_dark_factory-v0.7.3`, 2026-11-19 23:53 UTC, from `60c61751`). `main` was 82 commits ahead and the manifest still read 0.7.3.
- The repository is `dark-incorporated/bevy_dark_factory`. `bevy-coven` no longer exists. The old repository names redirect on the web and in the API, which is why nothing broke loudly. Some paths do **not** redirect: `bevy-coven/bevy_blueprint/issues/new` and `…/blob/main/CHANGELOG.md` return 404.

No check opened the built bundle, so three releases went out. `build_app.sh` now exits 1 when `CFBundleName` is not "Dark Factory" or the icon file the plist names is missing from the bundle.

## What changed

- **The name.** "Dark Factory", two words, in prose, UI, banner and docs (81 files, six commits). The plist, `build_app.sh`, the release workflow and the asset names follow: `Dark Factory.app`, `Dark-Factory-<V>-macos-arm64.{dmg,zip}`, volume "Dark Factory", release title "Dark Factory <V>". Kept one word on purpose, because they are identifiers and not prose: the User-Agent `DarkFactory/<v>`, `TERM_PROGRAM`, `~/Library/Caches/DarkFactory` and `Application Support/DarkFactory/feedback`.
- **The consequence.** `update.rs` looks for `Dark-Factory-<v>-macos-arm64.zip` with no fallback, so 0.7.1 to 0.7.3 cannot update themselves and must be reinstalled once from the DMG. A fallback to the old asset name would be a second path that installs a differently named bundle over the old one. About one install exists (each zip had been downloaded once).
- **The bundle identifier** is now `io.github.dark-incorporated.dark-factory`, folded into the same one-time reinstall.
- **Folders.** The folders the app makes in Documents are `Dark Factory Projects` and `Dark Factory Example`. Nothing is migrated: the owner's Documents only held `Cauldron Projects`.
- **#518.** `HEADING` is 11 px, so a heading outranks the 10 px label it heads (owner decision).

## The icon

Eighteen Retro Diffusion candidates through `dark_inc_art`, $1.96 in all (`rd_core` $0.10 each, `rd_pro` $0.18). Round one came back on opaque white backgrounds; naming the background in the prompt fixed it. The owner picked A, a gothic factory-cathedral with a rose-window gear under a magenta moon (seed 5201). It ships as ten sizes, 16 to 1024 px, with transparent corners, and `icon-jobs.json` records the exact job so it can be regenerated (managed skill `dark-factory-icon-regen`).

## The rehearsal, then the release

`release-macos.yml` was run with `publish=false sign=adhoc smoke=true` on the icon branch (run 44987924098, 18 min) before anything was tagged: checksums, DMG volume, plist, icon bytes identical to the committed file, and a smoke window reading "Welcome to Dark Factory v0.7.3".

**0.7.4** was tagged from `4e4a399f` (run 44991222857, **6 minutes**, warm). Sixteen of sixteen checks pass on the published release (`/tmp/dfart/verify-release.sh`): title "Dark Factory 0.7.4", three assets, `SHA256SUMS` verified, volume and plist right, the icon byte-identical to `crates/bevy_dark_factory/macos/AppIcon.icns`, and **Developer ID signed, hardened runtime, notarized and stapled** (`spctl`: accepted, source Notarized Developer ID). The notes lead with "reinstall once" and name the dead links as known. Releases 0.7.1 to 0.7.3 were retitled "Dark Factory": the updater reads the tag and the asset names, never the title.

**0.7.5** followed from `f3453f34` (`release: 0.7.5`, the same two lines as 0.7.4's bump; a version bump needs no second gate) once gate #3 passed (`main` `21fc2e35`, 5,048 / 5,048 in 842 s). Workflow run 44994666995; **17 of 17** checks, including the icon byte-comparison that my first version of `verify-release.sh` skipped without saying so (it looked at the wrong path; the comparison now runs and reports). The notes lead with "if you have 0.7.4, choose Update in the app", which makes 0.7.4 to 0.7.5 the first real use of the renamed in-app updater. **That has not been exercised by script**: there is no update smoke, only the `DARK_FACTORY_UPDATE_FEED` hook, so that it works is [INFERENCE] from reading `update.rs` (the feed address, the tag prefix, `Dark-Factory-<v>-macos-arm64.zip`, `SHA256SUMS` and `Dark Factory.app` inside the zip all match the published assets) until the owner presses Update.

**The release runner was re-registered** the same night (#534). `config.sh remove` cannot deregister a runner from an organization that no longer exists (it calls the old address's API and gets 404), so it was deregistered through the new address and registered again as id 73; a rehearsal (run 44995305239) took a job on it at once and passed. The steps and the trap are in the runbook.

## Decisions

- **Icon A**, and the model switch (every worker, reviewer and loop agent on `anthropic/claude-sonnet-5-5`; the two `therapist` agents stay on Opus 5.5), both saved permanently.
- **Reinstall once, no updater fallback, and a new bundle identifier.** One install exists; a shim would be a second path.
- **No migration of the folder names**, because nothing exists on the owner's disk to orphan.
- **0.7.4 before the link fix**, so the name and the icon were in the owner's hands first; 0.7.5 then doubles as the test that the renamed in-app updater works end to end.
- **#497: the window wins.** The terminal bar clips instead of pushing the pane past the window, so at text scale 3.0 the Invoke button is clickable; the maximised terminal's restored column count is 8 → 9, re-pinned with the owner's reason.
- **#525: soft wrap and syntax highlighting**, requested of gooey as bevy_gooey#114. **#501: approved and staged**, stage 1 first. **#494 stays open**: both local projects are empty.
