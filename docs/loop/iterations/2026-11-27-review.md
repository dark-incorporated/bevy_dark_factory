## The three findings that matter most

**1. A workspace switch tears down the whole interface, and three workspaces come back with a black viewport.**
A map → kit → map round trip on a fresh editor keeps 2 of 2,624 UI nodes; 2,598 are spawned new. That is the
frame #541 and #678 measure. On World, Kit and Animation the map's 45 mesh entities are 1, 6 and 13 and the
viewport's middle is 0.0 to 0.5% lit, where `vision.md`, `workspace.rs` and `screen.rs` all say those workspaces
share the map's viewport (#695). **Correction (same day):** I first wrote here that the cost vanished once the
frame profile had been opened. It did not: the profile's `Cmd+Shift+F` also fired the Shift-indifferent `Cmd+F`
filter row, a filter box took the keyboard, and every switch after it was **refused**, so it rebuilt nothing. The
last row of the table below is a refusal, not a cheap switch. Fixed in `fix/wave-1127` (#678).

| done just before the switch | longest wait for a frame, p50 | editor's `busy_ms`, p50 |
|---|---|---|
| nothing (fresh editor) | 218.2 ms | 188.9 |
| 75 s idle | 265.8 ms | 236.1 |
| palette opened and closed | 268.6 ms | 237.1 |
| Ctrl+J three times | 236.6 ms | 205.0 |
| Zen on and off | 262.5 ms | 234.2 |
| Ctrl+B on and off | 232.2 ms | 201.1 |
| frame profile on and off | 48.7 ms | 14.2 |

At rest the wait is 36 ms (one frame under Xvfb). The last row is the refused switch described above.

**2. The gate does not build what ships** (#687). The gate lints and tests the default features; the release
builds `--features family_all`. 16 modules (4,048 lines), 125 `cfg` sites and 119 tests in 43 files are outside
every gate. The editor says so itself: the gate's binary opens Sound on "This build has no audio panel."

**3. Every commit recompiles the editor** (#686). `build.rs` reruns when `HEAD` moves. Two gates whose only
change was a shell hook: 786 s and 794 s of test step for 362 s and 364 s of tests. About 430 s per gate, 47% of
a 920 s gate, roughly two hours of the last two days.

## Comments (lens 5): the owner's question

`crates/*/src`: 67,669 comment lines beside 180,641 code lines, **5.43 MB of 12.54 MB, about 1.36 M tokens**.
`chrome.rs` is 69% comment, `keys.rs` 66%, `tiles.rs` 53%, `editor.rs` 46% (5,318 of 14,422 lines, about
108,000 tokens to read one file). 405 comment lines carry a date, 936 say "measured" or "owner", 2,774 name an
issue.

Checked for truth, they hold up: of the line citations a script could test, the source comments had no wrong
one, the test comments five (#685), the docs five of 31. What went wrong this pass was three sentences that
*described a mechanism* (the shared viewport, the divider, the rect's top-left), and each was wrong in a
document too.

**Recommendation: not a ban.** A ban deletes the 936 lines that record a measurement or a decision, which are
the ones worth having. The cost is real, though, and it is in history told in place: what the code used to do,
which issue changed it, what was tried. That belongs in the commit. A rule that would cut most of the bulk and
keep the value: *a comment says what must stay true and why; it does not say what used to be true.* That is
checkable per file and could be applied to `chrome.rs` and `editor.rs` first to see what is left.
